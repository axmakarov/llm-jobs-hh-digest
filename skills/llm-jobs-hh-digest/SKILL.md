# Дайджест LLM-вакансий hh.ru → PDF «LLM JOBS»

На входе — диапазон дат публикации (например «7–14 октября», «с 01.10 по 07.10.2026», «за последнюю неделю»). На выходе — PDF A4: обложка, «Рынок за период» с графиком стека, вакансии по 7 группам ролей.

Файлы скилла лежат рядом с этим SKILL.md:
- `scripts/hh_llm.js` — сборщик, встраивается во вкладку hh.ru;
- `scripts/build_digest.py` + `scripts/style.css` — сборка PDF (CSS должен лежать рядом со скриптом);
- `examples/digest_example.json` — полный пример входа для сборщика PDF.

## Требования к среде — проверь первым делом

Скиллу нужен **браузер, в котором можно выполнить JavaScript на странице hh.ru** с куками живой сессии. Подходит любой из инструментов:

| Среда | Открыть страницу | Выполнить JS во вкладке |
|---|---|---|
| Claude Desktop (встроенный браузер) / Claude in Chrome | `navigate` / `preview_start` | `javascript_tool` |
| Claude Code + `chrome-devtools-mcp` | `new_page` / `navigate_page` | `evaluate_script` |
| Claude Code + Playwright MCP | `browser_navigate` | `browser_evaluate` |

Ниже «выполни JS» означает тот из этих инструментов, который есть в сессии. Если есть skill для браузера, прочитай его до первого шага.

**Если ни одного такого инструмента нет — остановись** и скажи пользователю: без браузера скилл не работает, а WebFetch, WebSearch и curl не подходят (hh отдаёт им неполную выдачу и капчу). Предложи подключить браузер, например `chrome-devtools-mcp` для Claude Code (см. README). Не подменяй сбор поиском по вебу.

Для PDF нужен Python 3 с `weasyprint` (плюс системные библиотеки Pango) и `pypdf` для проверки.

## 0. Разбор входа

- Приведи диапазон к `from`/`to` в формате YYYY-MM-DD, обе даты включительно; часовой пояс — московский. Если год не указан, бери текущий. Если указана одна дата, `from = to`.
- hh.ru ищет только по окнам 1, 3, 7 и 30 дней назад от сегодняшнего дня. Посчитай `days = сегодня − from + 1` и возьми наименьшее окно `period ≥ days`.
- Если `from` старше 30 дней, скажи пользователю: поиск hh.ru не покрывает такие даты, и предложи сократить диапазон до последних 30 дней. Не подменяй диапазон молча.
- Канал на кнопке «Подписаться» по умолчанию — `@llm_jobs` (https://t.me/llm_jobs). Если пользователь назвал другой, используй его.

## 1. Данные только через браузер

- Открой `https://hh.ru/search/vacancy?text=LLM&search_period=<period>&order_by=publication_time` и запомни вкладку.
- Прочитай `scripts/hh_llm.js` и выполни его текст целиком одним вызовом JS в этой вкладке. Он создаёт объект `window.LLMD` и возвращает `'LLMD ready'`.
- Вызов JS у браузерных инструментов обрывается по таймауту (обычно 30–60 с). Длинные задачи запускай в фоне без `await`, например `LLMD.collect(7); 'started'`. Прогресс проверяй отдельными вызовами: `await new Promise(r=>setTimeout(r,25000)); LLMD.progress()` (паузу держи меньше таймаута инструмента). Пользователю между опросами не пиши. Если он спросит, что происходит, коротко объясни: вкладка стоит на месте, а в фоне идёт загрузка, счётчик растёт.
- Не перезагружай и не уводи вкладку, пока идёт сбор: фоновая задача живёт в странице. Если вкладка всё же перезагрузилась, встрой скрипт заново — прогресс подтянется из `localStorage`.

### 1.1 Поиск
`LLMD.collect(period)` прогоняет 23 запроса по названию (LLM, GenAI, RAG, NLP, AI-агент, AI/ML-инженер, data scientist и др.) и полнотекстовый «LLM». Страницы выдачи загружаются в скрытых iframe: `fetch` отдаёт только 20 из 100 карточек. Жди, пока `progress().collectDone` станет `true`; в `log` есть строки вида «запрос: собрано / найдено hh». Обычно набирается 500–900 уникальных вакансий за неделю.

### 1.2 Карточки вакансий
`LLMD.details()` по очереди открывает страницы вакансий с паузой 1,2–2 с. Обрабатываются все вакансии из полнотекстового «LLM» и те, где AI/ML есть в названии. Скорость — около 25 вакансий в минуту. Каждые 20 вакансий прогресс сохраняется в `localStorage` вкладки.

**Капча.** Если `progress().captcha === true`, hh.ru попросил подтвердить, что вы не робот.
- Обходить капчу нельзя.
- Открой во вкладке любую страницу вакансии, убедись, что окно браузера видно пользователю, и попроси его пройти проверку.
- Затем снова вызови `LLMD.details()`: уже загруженные вакансии пропускаются.
- Не ускоряй загрузку и не запускай параллельные запросы: именно они вызывают капчу.

### 1.3 Отбор и статистика
`LLMD.analyze(from, to)` фильтрует вакансии по дате публикации, убирает архивные и оставляет те, где LLM — заметная часть работы:
- не меньше 5 упоминаний LLM-терминов, из них не меньше 3 разных;
- или LLM, GenAI, RAG, NLP, промпт или агент есть в названии и упоминаний не меньше 2.

Дубли одной вакансии в разных городах схлопываются. Метод возвращает:
- `total` — число LLM-вакансий за период;
- `byCountry`, `topCompanies`, `exp`, `formats`;
- `salary` — медиана, p25 и p75 по рублёвым месячным вилкам «на руки» (gross × 0,87) и `top` — самые высокие вилки;
- `stack` — топ-13 инструментов;
- `shortlist` — все отобранные вакансии в строках вида `id hits/distinct название — компания ×городов | дата`.

Ответ большой, поэтому выгружай `shortlist` частями: `LLMD.analyze(...).shortlist.slice(0,130)`.

## 2. Выбор вакансий в подборку

- Возьми 30–40 вакансий, где работа с LLM — суть роли: агенты, RAG, обучение, inference, оценка качества, безопасность, промпты, руководство LLM-направлением. Отбрасывай роли, где LLM упомянута вскользь: SEO, маркетинг, ИБ общего профиля, «пользуемся ChatGPT».
- Нужно разнообразие: разные компании и уровни, удалёнка и офис, Россия и другие страны. Одного крупного работодателя — не больше 4–5 позиций.
- Предпочитай вакансии с указанной зарплатой и редкие роли: alignment, inference, безопасность AI, оценка качества.
- Тексты выгружай через `LLMD.export([...ids])` по 12–13 вакансий за вызов, иначе ответ обрежется. Прочитай каждое описание, прежде чем писать пересказ.
- Каждой вакансии назначь одну категорию:

| Ключ | Группа | Кого сюда |
|---|---|---|
| `agents` | Агентные платформы и AI-продукты | Агенты и LLM-продукты для клиентов и рынка, стартапы |
| `corp` | Корпоративные ассистенты и RAG | Внутренние ассистенты, RAG, внедрение LLM в процессы |
| `train` | Обучение и дообучение моделей | SFT, alignment, RL, обучение с нуля, R&D |
| `infra` | Инфраструктура, inference, LLMOps | GPU, vLLM, LLM-шлюзы, on-prem платформы, MLOps |
| `sec` | Безопасность AI | Атаки на LLM и агентов, защитные механизмы |
| `eval` | Оценка качества, промпты, аналитика | Приёмки моделей, AI-тренеры, промпт-инженеры, аналитики |
| `lead` | Руководство и архитектура | Руководители, архитекторы решений, стратегия |

## 3. Тексты

- **Пересказ вакансии** — 1–2 предложения, до ~45 слов, своими словами. Что делать, на каком стеке, чем роль необычна. Не копируй фразы из описания. Не повторяй формат, зарплату, опыт и город: они выводятся отдельными пометками.
- **Пометки:**
  - `format` из `workFormats`: «Удалёнка», «Гибрид», «Офис», сочетания через « · ». Особые условия добавляй в скобках: «Офис (5/2)».
  - `exp`: «1–3 года», «3–6 лет», «6+ лет», «Без опыта». Если текст вакансии противоречит полю hh, бери текст.
  - `city`: город; «N городов», если вакансия опубликована в нескольких; «Город (релокация)».
  - `salary`: «80–120 тыс. ₽ на руки», «от 140 тыс. ₽ gross», «до 310 тыс. ₽ на руки», «$5 200–8 700 gross», «$4 500–5 500». Пустая строка, если зарплата не указана.
- **«Рынок за период»** строится из `analyze`:
  - `lead` — одно предложение-вывод;
  - 4 факта: география, работодатели, опыт, формат — с числами и процентами;
  - `salary_html` — сколько вакансий с зарплатой, медиана, половина вилок, потолок с названиями работодателей; можно выделить `<b>`;
  - `chart_title` — вывод про лидера стека, например «RAG требуют в двух из трёх LLM-вакансий»;
  - `stack_note` — 1–2 предложения о стеке;
  - `method` — как собран срез: дата сбора, запросы, сколько просмотрено, что отброшено. Дату сбора берёшь как сегодняшнюю.
- `period.label` — «7–14 октября 2026»; `period.short` — «7–14.10.2026». Если месяцы разные: «28 сентября — 4 октября 2026», «28.09–04.10.2026».

## 4. Сборка PDF

1. Проверь инструменты: `python3 -c "import weasyprint"`. Если модуля нет — поставь в виртуальное окружение (`pip install weasyprint pypdf`); на macOS WeasyPrint нужен ещё `brew install pango`. Шрифт Inter: `fc-list | grep -i Inter`; без него сработает запасной DejaVu Sans.
2. Создай рабочую папку и запиши в неё `digest.json` (схема ниже). Скрипты не копируй — запускай из папки скилла.
3. Запусти `python3 <папка скилла>/scripts/build_digest.py <рабочая папка>/digest.json <рабочая папка>/out`. Файл получит имя `LLM_JOBS_vakansii_<from>_<to>.pdf`; своё имя можно задать полем `filename`.
4. Проверь результат:
   - растеризуй 2–3 страницы (`pdftoppm -r 60 -png` или `pypdfium2`) и посмотри глазами: ничего не обрезано и не наезжает, обложка чистая;
   - через pypdf посчитай аннотации `/URI`: ссылок на hh.ru столько же, сколько вакансий, ссылка на канал есть;
   - закладки PDF: разделы → группы → вакансии;
   - внутри каждой группы даты идут от новых к старым.
5. Отдай PDF пользователю: если в среде есть папка для результатов или инструмент отправки файла — используй их, иначе назови полный путь к файлу.
6. Очисти следы во вкладке hh.ru: `LLMD.cleanup()`.
7. Ответ пользователю — 2–4 строки: сколько найдено и сколько вошло в подборку, как устроен PDF.

### Подводные камни (уже наступали)
- WeasyPrint не делает кликабельными ссылки внутри flex-контейнеров. Шапку, подвал карточки и кнопку верстай без flex — так и сделано в `style.css`.
- В WeasyPrint `outline` рисуется прямоугольником; свечение кнопки сделано рамкой-обёрткой `.ring`.
- У `<template id="HH-Lux-InitialState">` нужно читать `innerHTML`, а не `textContent`: тот пустой.
- Дата публикации на hh — это время последней публикации, вакансию могли переопубликовать. Это нормально, бери её как есть.
- Вакансии одного дня в выдаче идут от новых к старым. Сохраняй этот порядок в `vacancies`: сборщик сортирует по дате и при равенстве оставляет исходный порядок.
- Вёрстка hh.ru меняется. Если `collect` находит 0 вакансий или `details` падает на `HH-Lux-InitialState`, проверь селекторы `data-qa` и структуру JSON на живой странице и скажи пользователю, что сломалось, — не выдумывай данные.

## digest.json — схема

```json
{
  "period": {"from": "2026-10-07", "to": "2026-10-14", "label": "7–14 октября 2026", "short": "7–14.10.2026"},
  "channel": {"handle": "@llm_jobs", "url": "https://t.me/llm_jobs"},
  "stats": {
    "total": 252,
    "lead": "Спрос сосредоточен в России и в крупных компаниях: …",
    "facts": [
      {"k": "География", "v": "Россия — 212 из 252, Казахстан — 14, …"},
      {"k": "Работодатели", "v": "Сбер — 45, «ГигаЧат Бизнес» — 10, Ozon — 8; …"},
      {"k": "Опыт", "v": "3–6 лет — 134 (53%), 1–3 года — 64, …"},
      {"k": "Формат", "v": "Только офис — 105 (42%), гибрид — 54, удалёнка возможна в 93 (37%)."}
    ],
    "salary_html": "Указаны лишь в 64 вакансиях (25%). Медиана … — около <b>160 тыс. ₽ на руки</b>, …",
    "chart_title": "RAG требуют в двух из трёх LLM-вакансий",
    "stack": [["RAG", 164], ["LangChain", 84], ["MCP", 75]],
    "stack_note": "Стек периода — RAG, агентные фреймворки, MCP и API готовых моделей. …",
    "method": "Срез сделан 14 октября: полнотекстовый поиск «LLM» на hh.ru (607 вакансий) плюс поиск по названиям …, всего 779 вакансий. …"
  },
  "vacancies": [
    {"id": "137372651", "role": "AI/LLM Engineer", "company": "Российские железные дороги", "date": "2026-10-14",
     "city": "Москва", "format": "Офис", "exp": "1–3 года", "salary": "", "cat": "infra",
     "summary": "Владелец on-premise LLM-инфраструктуры без внешних API: …"}
  ]
}
```
`stack` — до 13 пар «инструмент, число вакансий» из `analyze().stack`; проценты сборщик считает от `total`. Порядок `vacancies` — как в выдаче hh: от новых к старым. Полный пример — `examples/digest_example.json`.
